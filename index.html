Plates 44 and 45 of the field guide

Two agents that land in a stranger's environment and leave working test infrastructure behind.

Plate 44 points a real browser at a running web app, records what is broken, and provisions a complete Playwright + Playwright MCP project with page objects, a smoke suite and CI. Plate 45 reads whatever legacy test estate already exists — Selenium in Java, Python, C# or JavaScript, Cucumber, Postman, markdown test plans — and rebuilds it as one standardised Playwright architecture with a migration report that lists every line it could not convert. Both run to completion with no model at all; a local open-weight model only polishes text.

What "agent" means here

Scoped automation, not a chat assistant.

Each agent is one folder under src/agents/, one CLI, a handful of REST routes and a node:test suite. Every deliverable exists with LLM_PROVIDER=none: the crawl, the findings, the generated project, the report. Both persist to the same SQLite database (engagements, runs, findings, artifacts) through Node's built-in node:sqlite, so every number in a report can be traced to a run id and every generated file to an artifact row. The only model the adapter will talk to is one you run yourself; public endpoints are rejected.

"One job, one contract — composable, scriptable, and boring by design."

Part 2

Standardising what already exists

Most organisations do not start from nothing; they start from a selenium-java module nobody has run since the last Chrome upgrade, a Python folder a contractor left, a .feature file whose step definitions drifted and a Postman collection with the real API expectations buried in pm.test scripts. The SDET Architect inventories all of it and emits one architecture, one MIGRATION.md, and a TODO(sdet-architect) comment for every line a human still has to think about.
