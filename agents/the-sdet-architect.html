Standardising what already exists

The SDET Architect

Inventories any legacy test estate (Selenium in any language, Cucumber, Postman, test plans) and rebuilds it as one standardised Playwright + Playwright MCP architecture, offline.

Source: src/agents/the-sdet-architect/  ·  Doc: docs/agents/the-sdet-architect.md  ·  Tests: tests/the-sdet-architect/

  • Point it at a folder. Selenium in Java, Python, C# or JavaScript, Cypress, Cucumber, Postman and markdown test plans all parse into one model.
  • Regex and line-based parsers only: no AST libraries, no language runtimes.
  • Standardises every locator into the most robust Playwright form, with a confidence score.
  • Generates one project: page objects, fixtures, specs, playwright-bdd steps, API specs, config, CI, .mcp.json.
  • Writes MIGRATION.md with every line it could not convert and its source file:line.
  • Fixture estate, run 46f19623 on 2026-09-11: 12 files, 28 tests, 24 / 2 / 2, 99 of 108 steps (91.7%), 38 locators, 3 low, 26 files. Deterministic with no model.

At a glance

Why this exists

The chore it removes
  • A Selenium module nobody has run since the last Chrome upgrade; a .NET project that builds on one laptop.
  • A .feature file whose steps drifted; a Postman collection with the real expectations in pm.test scripts.
  • Three weeks of reading; a locator spreadsheet stale the day it is finished.
→
What you get instead
  • One run, one architecture.
  • A per-file status table, a TODO list with file:line on every row, a confidence histogram.
  • The human work is the TODO list, not the reading.
  • The process page puts this agent under the eval cube as the deterministic regression layer.
  • An organisation cannot tell whether an AI deployment broke something unless its existing tests run, and they usually do not.
  • The same page objects serve an MCP client for exploratory checks.

3 worked examples from real runs

Run it & wire it in

You can run this yourself, end to end — every command below is real.

Before you start

  • Node 24 and npm install in the repo. No Java, Python or .NET toolchain: the parsers read text.
  • A folder with the legacy estate, as an absolute path. The bundled fixtures/sdet-architect is a fabricated one to try first.
  • Optionally the application's base URL; otherwise the most common navigated origin is detected.

Step by step

  1. Install and initialise
    npm install
npm run db:init
    Why Same database as the Forward Deployed Tester; both agents write to data/forward-qa.db.
  2. Run it on the bundled fabricated estate
    LLM_PROVIDER=none npm run agent:sdet -- --src "$PWD/fixtures/sdet-architect" --org fabricated-shop
    Why
    • Twelve files: Java, Python, C# and JavaScript Selenium, a .feature, a Postman collection, a markdown test plan, two config files.
    • Prints the output JSON and the path of MIGRATION.md.
    First run Run 46f19623 on 2026-09-11: 12 files, 28 tests, 24 / 2 / 2, 38 locators, 3 low, 91.7% coverage, 26 files written.
    Re-run Byte-for-byte identical output under LLM_PROVIDER=none; a new run id and directory each time.
  3. Run it on a real estate
    npm run agent:sdet -- --src /abs/path/to/legacy-tests --org acme --base-url https://app.acme.example.test
npm run agent:sdet -- --src /abs/path/to/legacy-tests --org acme --include "**/*.java" --exclude "**/archive/**"
npm run agent:sdet -- --src /abs/path/to/legacy-tests --org acme --dry-run
    Why
    • --include / --exclude are globs relative to source_dir, added to the default excludes.
    • --dry-run computes everything, writes nothing, and still returns the full MIGRATION.md text in the output JSON.
  4. Read MIGRATION.md top-down
    cat workspace/<run_id>/playwright/MIGRATION.md
    Why Eight sections: header numbers, inventory, per-file status, TODO list, locator confidence, findings, generated tree, next steps, MCP. grep -rn "TODO(sdet-architect)" in the output gives the same TODO list.
  5. Typecheck and run the generated project
    cd workspace/<run_id>/playwright
npm install
npx playwright install --with-deps
npm run typecheck
BASE_URL=https://staging.acme.example.test npm test -- --project=chromium
    Why
    • The repo's end-to-end test already compiles the generated project with tsc, so typecheck is the first gate.
    • The fabricated estate targets https://shop.example.test, which does not exist, so npm test there fails at navigation by design.
    • Against a real estate, run one spec at a time and work the TODO list.
    First run On the fixture estate typecheck passes; the specs cannot pass because the site is fictional.
  6. Convert one file without touching disk
    npm start
curl -s -X POST localhost:8787/agents/sdet-architect/preview -H 'content-type: application/json' \
  -d "{\"language\":\"java\",\"code\":$(jq -Rs . < LoginTest.java)}" | jq -r .spec
    Why Classifies, parses, plans and generates for one file and returns the spec plus tests_found, todos, coverage_pct. Nothing written, no run row.
  7. Drive the generated pages from an MCP client
    cd workspace/<run_id>/playwright
npm run mcp    # mcp-server-playwright --config playwright-mcp.config.json
    Why .mcp.json and playwright-mcp.config.json come with the project; src/pages/*.page.ts is the vocabulary for exploratory checks.
  8. Run the agent's own tests
    npm test
    Why Parsers for every dialect, the locator table, the emitters, the inventory, and one end-to-end run over the fixture that also tsc-compiles the output.
    First run Part of the 89 green tests on 2026-09-11.

What you give it

--src / source_dir
Absolute path to the legacy estate.
--org / org_slug
Names the generated package (<org>-playwright) and the report.
--include, --exclude
Globs relative to the estate; **, *, ?, {a,b} supported.
--base-url / base_url
Optional; else detected from the most common navigated origin, ignoring api.* hosts.
--language-hint / language_hint
java python csharp javascript typescript auto (default).
--dry-run / dry_run
Compute everything, write nothing.

What comes back

workspace/<run_id>/playwright/
The standardised project: src/pages, src/fixtures, tests, tests/features, tests/steps, tests/api, config, CI, .mcp.json, MIGRATION.md.
Output JSON
inventory, files_scanned, tests_found, tests_converted, tests_partial, tests_manual, locators_total, locators_low_confidence, coverage_pct, output_dir, migration_report.
Rows in findings and artifacts
Five finding categories; one artifact per generated file with its kind.
GET /agents/sdet-architect/runs/:id/migration
MIGRATION.md as text/markdown, straight from the run's output JSON.
Running it again.
  • Deterministic: same estate, same options, same bytes. A second run after someone edits the legacy code is a clean diff of the generated project.
  • Runs are never overwritten.
  • With a local model, only the suggestion: comments next to TODOs can differ; the code lines cannot.
Plug it into your stack.
  • Move workspace/<run_id>/playwright into the application repo; keep MIGRATION.md at its root as the work list; wire the workflow into CI.
  • Work the TODO list top-down; delete the NOTE(sdet-architect) lines once the specs are green three runs in a row.
  • To support another dialect: one parser returning a TestSuite (see parsers/selenium-python.ts, ~110 lines) plus one case in classifyFile and parseOne.
  • In the engagement on the process page, this project is the regression layer that runs on every change during and after the pilot.

The intermediate model

When it runs
Phase b, every parser targets it.
Takes in
Source text.
Shows out
A TestSuite: tests[], pageObjects[], hooks[], locators[], urls[], constants, plus feature, stepDefinitions or requests; every Step carries kind, locator, value / valueExpr, assertion, raw, line — see model.ts.
3 / 7

Normalisation and scope

When it runs
Per statement, inside every method body.
Takes in
One statement and the method's Scope (elements, By variables, typed values, page-object variables, parameters, constants).
Shows out
A token string such as «E0».sendKeys(«S1») and the side tables that resolve the tokens — via normalize(), resolveConcat().
4 / 7

Locator confidence

When it runs
Once per unique strategy:value, cached in the plan.
Takes in
A Locator and the estate-wide testIdAttribute decision.
Shows out
A StdLocator with expr, confidence and a note when under 0.60 — via standardize(), standardizeXpath(), chooseTestIdAttribute().
5 / 7

Plan, pages, fixtures

When it runs
Phase c, before any code is emitted.
Takes in
All suites.
Shows out
Planned pages with unique class names, files, fixture names and fields; src/fixtures/index.ts extending test with one fixture per page — via buildPlan(), genFixtures().
6 / 7

Findings and MIGRATION.md

When it runs
Phase d, after generation, before the write.
Takes in
The GenerateOutput.
Shows out
Rows in findings (locator, conversion, flakiness, duplication, quality) and the eight-section report — via run() and buildMigrationReport().
7 / 7

Preview, no disk, no database

On POST /agents/sdet-architect/preview.
Takes in
{ language?, code, filename?, base_url? }.
Shows out
{ kind, output_file, spec, tests_found, todos, coverage_pct } for that one file — via preview(), nothing written.
