Standardising what already exists

The SDET Architect

Inventories any legacy test estate (Selenium in any language, Cucumber, Postman, test plans) and rebuilds it as one standardised Playwright + Playwright MCP architecture, offline.

Source: src/agents/the-sdet-architect/  ·  Doc: docs/agents/the-sdet-architect.md  ·  Tests: tests/the-sdet-architect/

Point it at a folder. It classifies every file, parses Java, Python, C# and JavaScript Selenium (plus Cypress, Cucumber features and step definitions, Postman collections and markdown test plans) into one intermediate model with regex and line-based parsers — no AST libraries, no language runtimes — standardises every locator into the most robust Playwright form with a confidence score, and generates a single project: page objects, fixtures, specs, playwright-bdd steps, API specs, config, CI, .mcp.json and a MIGRATION.md that lists every line it could not convert with its source file:line. On the bundled fabricated estate (run 46f19623, 2026-09-11) it scanned 12 files, found 28 tests, converted 24 fully and 2 partially, left 2 as test.fixme scaffolds, emitted 99 of 108 steps as Playwright (91.7%), standardised 38 unique locators with 3 below the 0.60 review line, and wrote 26 files. With LLM_PROVIDER=none the output is byte-for-byte deterministic.

Why this exists

The chore it removes

Every engagement starts with archaeology. A selenium-java module nobody has run since the last Chrome upgrade, a Python folder a contractor left behind, a .NET project that builds on one laptop, a .feature file whose step definitions drifted, a Postman collection with the real API expectations buried in pm.test scripts, and a markdown test plan that is the only honest description of what the business cares about. Someone senior spends three weeks reading all of it, keeps a spreadsheet of locators, hand-writes Playwright — and the spreadsheet is stale the day it is finished.

→
What you get instead

One run. One architecture. A MIGRATION.md with a per-file status table, a numbered TODO list where every row carries its source file:line, a locator-confidence histogram, and findings in five categories. The human work is the TODO list, not the reading.

The process page puts this agent underneath the eval cube as the deterministic regression layer: an organisation cannot tell whether an AI deployment broke something unless its existing tests run, and they usually do not. Standardising them onto Playwright + MCP is also what lets an MCP client reuse the same page objects the specs use for exploratory checks.

What this step does

See it in action

Run it & wire it in

You can run this yourself, end to end — every command below is real.

Before you start

  • Node 24 and npm install in the repo. No Java, Python or .NET toolchain is needed: the parsers read text.
  • A folder with the legacy estate, given as an absolute path. The bundled fixtures/sdet-architect is a fabricated one you can try first.
  • Optionally the real application's base URL; otherwise the most common navigated origin in the estate is detected.

Step by step

  1. Install and initialise
    npm install
npm run db:init
    Why Same database as the Forward Deployed Tester; both agents write to data/forward-qa.db.
  2. Run it on the bundled fabricated estate
    LLM_PROVIDER=none npm run agent:sdet -- --src "$PWD/fixtures/sdet-architect" --org fabricated-shop
    Why Twelve files across Java (JUnit-style page object, TestNG tests, Cucumber steps), Python (pytest), C# (NUnit), JavaScript (selenium-webdriver + mocha), a .feature, a Postman collection, a markdown test plan and two config files. The CLI prints the output JSON and the path of MIGRATION.md.
    First run Run 46f19623 on 2026-09-11: 12 files, 28 tests, 24 / 2 / 2, 38 locators, 3 low, 91.7% coverage, 26 files written.
    Re-run Byte-for-byte identical output under LLM_PROVIDER=none; a new run id and directory each time.
  3. Run it on a real estate
    npm run agent:sdet -- --src /abs/path/to/legacy-tests --org acme --base-url https://app.acme.example.test
npm run agent:sdet -- --src /abs/path/to/legacy-tests --org acme --include "**/*.java" --exclude "**/archive/**"
npm run agent:sdet -- --src /abs/path/to/legacy-tests --org acme --dry-run
    Why --include / --exclude are globs relative to source_dir and add to the default excludes. --dry-run computes everything, records nothing to disk, and still returns the full MIGRATION.md text in the output JSON — useful for a first look at coverage before committing to a workspace.
  4. Read MIGRATION.md top-down
    cat workspace/<run_id>/playwright/MIGRATION.md
    Why Eight sections: header numbers, inventory, per-file status, the TODO list, locator confidence, findings summary, the generated tree, next steps, and how to run from an MCP client. Every TODO row carries the same [file:line] that appears as a comment in the generated code, so grep -rn "TODO(sdet-architect)" in the output gives the same list.
  5. Typecheck and run the generated project
    cd workspace/<run_id>/playwright
npm install
npx playwright install --with-deps
npm run typecheck
BASE_URL=https://staging.acme.example.test npm test -- --project=chromium
    Why The end-to-end test in the repo (tests/sdet-architect/e2e.test.ts) already compiles the generated project with tsc, so typecheck is the first gate. For the fabricated estate the base URL https://shop.example.test does not exist, so npm test there fails at navigation by design; against a real estate, run one spec at a time and work the TODO list.
    First run On the fixture estate typecheck passes; the specs cannot pass because the site is fictional.
  6. Convert one file without touching disk
    npm start
curl -s -X POST localhost:8787/agents/sdet-architect/preview -H 'content-type: application/json' \
  -d "{\"language\":\"java\",\"code\":$(jq -Rs . < LoginTest.java)}" | jq -r .spec
    Why The preview route classifies, parses, plans and generates for a single file and returns the spec text plus tests_found, todos and coverage_pct. Nothing is written and no run row is created — a good way to show a sceptical team what their LoginTest.java becomes.
  7. Drive the generated pages from an MCP client
    cd workspace/<run_id>/playwright
npm run mcp    # mcp-server-playwright --config playwright-mcp.config.json
    Why .mcp.json and playwright-mcp.config.json are generated with the project. An MCP client can navigate to the base URL and use src/pages/*.page.ts as the vocabulary for exploratory checks — the same locators the specs use.
  8. Run the agent's own tests
    npm test
    Why Parsers for every dialect, the locator table, the emitters, the inventory and one end-to-end run over the fixture that also tsc-compiles the output.
    First run Part of the 89 green tests on 2026-09-11.

What you give it

--src / source_dir
Absolute path to the legacy estate.
--org / org_slug
Names the generated package (<org>-playwright) and the report.
--include, --exclude
Globs relative to the estate; **, *, ?, {a,b} supported.
--base-url / base_url
Optional; else detected from the most common navigated origin, ignoring api.* hosts.
--language-hint / language_hint
java python csharp javascript typescript auto (default).
--dry-run / dry_run
Compute everything, write nothing.

What comes back

workspace/<run_id>/playwright/
The standardised project: src/pages, src/fixtures, tests, tests/features, tests/steps, tests/api, config, CI, .mcp.json, MIGRATION.md.
Output JSON
inventory, files_scanned, tests_found, tests_converted, tests_partial, tests_manual, locators_total, locators_low_confidence, coverage_pct, output_dir, migration_report.
Rows in findings and artifacts
Five finding categories; one artifact per generated file with its kind.
GET /agents/sdet-architect/runs/:id/migration
MIGRATION.md as text/markdown, straight from the run's output JSON.
Running it again. Deterministic: the same estate and options give the same bytes, so a second run after someone edits the legacy code is a clean diff of the generated project — that is how to see whether a refactor of the old suite raised or lowered coverage. Runs are never overwritten. With a local model configured, only the suggestion: comments next to TODOs can differ between runs; the code lines cannot.
Plug it into your stack. Move workspace/<run_id>/playwright into the application repository, keep MIGRATION.md at its root as the work list, and wire the generated workflow into CI; it already sets BASE_URL from a repository variable with the detected default. Work the TODO list top-down, then delete the NOTE(sdet-architect) lines once the specs are green three runs in a row. To support another legacy dialect, add a parser that returns a TestSuite (see parsers/selenium-python.ts for a ~110-line example) and one case in classifyFile and parseOne; the planner, emitters and report need no change. In the engagement on the process page this project is the regression layer that runs on every change during and after the pilot.

Under the hood — for the curious

1 / 7

Inventory

When it runs
Phase a, the only part that reads the filesystem.
Takes in
source_dir, optional include / exclude globs, language_hint.
Shows out
One InventoryEntry per file (path, kind, bytes, lines, language) and a Map of contents — via inventory(), globToRegExp(), classifyFile().
2 / 7

The intermediate model

When it runs
Phase b, every parser targets it.
Takes in
Source text.
Shows out
A TestSuite: tests[], pageObjects[], hooks[], locators[], urls[], constants, plus feature, stepDefinitions or requests for the non-Selenium kinds; every Step carries kind, locator, value / valueExpr, assertion, raw and line — see model.ts.
3 / 7

Normalisation and scope

When it runs
Per statement, inside every method body.
Takes in
One statement and the method's Scope (elements, By variables, typed values, page-object variables, parameters, constants).
Shows out
A token string such as «E0».sendKeys(«S1») and the side tables that resolve the tokens — via normalize(), resolveConcat().
4 / 7

Locator confidence

When it runs
Once per unique strategy:value, cached in the plan.
Takes in
A Locator and the estate-wide testIdAttribute decision.
Shows out
A StdLocator with expr, confidence and a note when it is under 0.60 — via standardize(), standardizeXpath(), chooseTestIdAttribute().
5 / 7

Plan, pages, fixtures

When it runs
Phase c, before any code is emitted.
Takes in
All suites.
Shows out
Planned pages with unique class names, files, fixture names and fields; src/fixtures/index.ts extending test with one fixture per page — via buildPlan(), genFixtures().
6 / 7

Findings and MIGRATION.md

When it runs
Phase d, after generation, before the write.
Takes in
The GenerateOutput.
Shows out
Rows in findings (locator, conversion, flakiness, duplication, quality) and the eight-section report — via run() and buildMigrationReport().
7 / 7

Preview, no disk, no database

When it runs
On POST /agents/sdet-architect/preview.
Takes in
{ language?, code, filename?, base_url? }.
Shows out
{ kind, output_file, spec, tests_found, todos, coverage_pct } for that one file — via preview(), the same parsers and generators, nothing written.
