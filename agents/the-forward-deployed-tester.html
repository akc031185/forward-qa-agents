The Forward Deployed Tester

Point it at a running web app; it crawls, records findings and provisions a complete Playwright + MCP test project in one run.

Source: src/agents/the-forward-deployed-tester/  ·  Doc: docs/agents/the-forward-deployed-tester.md  ·  Tests: tests/the-forward-deployed-tester/

  • Launches a real Chromium through Playwright and crawls every same-origin page from target_url, breadth-first.
  • Harvests the accessibility tree and picks one Playwright locator per element, each with a confidence.
  • Writes severity-graded findings to the shared SQLite database.
  • Provisions a runnable Playwright + Playwright MCP project: page objects, smoke suite, consoleErrors fixture, CI, README, .mcp.json.
  • Writes report.md and report.json. The 2026-09-11 04:32 run: 3 pages in 2.0 s, 4 findings, 9 locators, 11 files.
  • Needs no model. On the process page it is the surface probe of the Discover phase.

At a glance

Why this exists

The chore it removes
  • A week of clicking through the app and pasting URLs into a spreadsheet.
  • A config copied from a blog post, page objects with brittle CSS, a CI job nobody trusts.
  • Obvious defects go unrecorded because "we are still setting up".
→
What you get instead
  • One command, one run id.
  • A crawl table, findings by severity with evidence, a locator inventory with confidences.
  • A project you can npm test on the first run, and a report you can hand to the client.
  • Vendors' forward-deployed engineers deliver the AI; nobody independently measures what they delivered.
  • Measurement needs a deterministic regression layer that exists before the pilot starts.
  • This agent makes that layer exist on day one, from the running app alone.

3 worked examples from real runs

Run it & wire it in

You can run this yourself, end to end — every command below is real.

Before you start

  • Node 24 (the built-in node:sqlite driver needs it).
  • A clone of the repo and npm install: Playwright, Fastify and zod, nothing else.
  • Any running web app you are allowed to crawl. Same-origin links only; forms are never submitted.

Step by step

  1. Install and fetch a browser
    npm install
npx playwright install chromium
    Why The crawler launches Chromium through Playwright. The generated project installs all three engines later with --with-deps.
    First run Done on 2026-09-11 while building the repo.
  2. Create the database
    npm run db:init
    Why Creates data/forward-qa.db with engagements, runs, findings, artifacts. Idempotent; every run applies the same schema on open.
    Re-run Safe to repeat; nothing is dropped.
  3. Run it against a URL
    LLM_PROVIDER=none npm run agent:fdt -- --url https://app.example.test --org acme --max-pages 10

# behind basic auth, or with a session cookie
npm run agent:fdt -- --url https://staging.example.test --org acme --basic-user qa --basic-pass secret
npm run agent:fdt -- --url https://app.example.test --org acme --cookie "session=abc123" --cookie-domain app.example.test
    Why
    • Creates an engagement, runs the agent, prints the output JSON and the run id.
    • LLM_PROVIDER=none makes the run reproducible; unset, the adapter probes for a local Ollama.
    First run 2026-09-11 04:32 against a local three-page site: 3 pages, 4 findings, 9 locators, 11 files, 2.0 s.
    Re-run A new run id, workspace directory and rows; earlier runs are never modified.
  4. Read the report
    cat workspace/<run_id>/report.md
cat workspace/<run_id>/run.log
    Why Summary, crawl table, broken links, findings by severity, locator inventory per page, provisioned files, next steps. run.log has one timestamped line per phase and visit.
  5. Run what it built
    cd workspace/<run_id>/infra
npm install
npx playwright install --with-deps
npm test
BASE_URL=https://staging.example.test npm test
    Why Green on the first run against the same environment; a red test is a regression or one of the findings. BASE_URL points the suite at another environment.
    First run The /about test carries a NOTE instead of an h1 assertion because recon found no heading.
  6. Same thing through the REST API
    npm start   # http://localhost:8787
curl -s -X POST localhost:8787/engagements -H 'content-type: application/json' \
  -d '{"org":"acme","name":"first pass","target_url":"https://app.example.test"}'
curl -s -X POST localhost:8787/agents/forward-deployed-tester/runs -H 'content-type: application/json' \
  -d '{"engagement_id":"<id>","input":{"target_url":"https://app.example.test","org_slug":"acme","max_pages":10}}'
curl -s localhost:8787/agents/forward-deployed-tester/runs/<run_id>/report
    Why Synchronous: the POST returns { run, output } when the crawl is done. Invalid input is a 400 with zod issues.
  7. Hand the MCP config to a client
    cd workspace/<run_id>/infra
cat .mcp.json
npm run mcp    # or let Claude Code / Cursor launch it from .mcp.json
    Why .mcp.json registers the Playwright MCP server with BASE_URL set to the crawled site. The generated README lists three prompts to start with.
  8. Run the agent's own tests
    npm run typecheck
npm test
    Why 89 tests across both agents; integration.test.ts drives the real crawler through Chromium against an in-process server.
    First run 89 pass, 0 fail, 2.9 s on 2026-09-11.

What you give it

--url / target_url
Start page; the crawl never leaves its origin.
--org / org_slug
Letters, digits, - and _. Names the generated package and the report.
--max-pages / max_pages
1–50, default 15. Rendered pages only.
--timeout-ms / timeout_ms
1000–120000, default 15000. Per navigation.
--basic-user + --basic-pass, or --cookie + --cookie-domain
Optional auth. Cookies are name=value;name2=value2.
--headed, --no-mcp
Watch the browser; skip the MCP files.

What comes back

workspace/<run_id>/infra/
The provisioned project: 8 fixed files plus one page object per page.
workspace/<run_id>/report.md and report.json
Human and machine forms of the same report.
workspace/<run_id>/run.log
Timestamped phase and visit log.
Rows in runs, findings, artifacts
Queryable through GET /runs/:id, /runs/:id/findings, /runs/:id/artifacts.
Running it again.
  • Nothing is cached or overwritten: every run gets a fresh run id, directory and rows.
  • Re-run after a deploy and diff the two report.json files: new broken links, console errors or locator changes are the regression signal.
  • Raise max_pages when the report says links were skipped.
Plug it into your stack.
  • Commit workspace/<run_id>/infra into the application repo as its e2e/ folder; the workflow runs on push, PR, nightly and manual dispatch.
  • Set BASE_URL per environment through repository variables.
  • In the engagement on the process page, this run is the Discover-phase probe; its findings and smoke suite are the baseline later phases measure against.
  • To add a probe of your own, follow the same shape: a pure derive*() function, rows through ctx.db, files through string builders, registered in src/api/server.ts.

Under the hood — for the curious

A slide for each moving part. Slide back and forth.

1 / 6

Queue and budgets

When it runs
Phase 1 of 4, once per run.
Takes in
target_url, max_pages, timeout_ms, headless, optional auth.
Shows out
A CrawlResult: rendered pages, brokenLinks, skipped URLs and durationMs — via crawl(), normaliseUrl(), isCrawlable().
2 / 6

In-page harvest

When it runs
Inside every successful visit, after load and up to 2 s of network idle.
Takes in
The live DOM, and maxElements = 60.
Shows out
A HarvestResult: title, h1, landmark flag, alt and label counts, element counts, same-origin links, up to 60 descriptors — via HARVEST_SCRIPT.
3 / 6

Locator derivation

When it runs
Back in Node, for every harvested descriptor.
Takes in
Tag, type, role, accessible name, label, placeholder, text, test id, id, name attribute, classes.
Shows out
A DerivedLocator with strategy, Playwright code and confidence, plus a unique camelCase property name — via deriveLocator(), toPropertyName(), uniqueNames().
4 / 6

Findings

When it runs
Phase 2, after the crawl, before anything is written.
Takes in
The CrawlResult.
Shows out
Rows in findings with severity, category, title, detail and evidence JSON — via deriveFindings() and Db.addFinding().
5 / 6

Provisioning and persistence

When it runs
Phases 3 and 4.
Takes in
The page records and the run options.
Shows out
11+ files under workspace/<run_id>/infra, one artifacts row each; report.md, report.json, run.log; the runs row marked succeeded — via generateInfra(), renderReportMarkdown(), buildReportJson(), executeAgent().
6 / 6

Optional local model

When it runs
Only in phase 4, only if a local server answers within 800 ms.
Takes in
The deterministic summary and a prompt that forbids new facts.
Shows out
A rephrased summary, or the original — via maybeLlm(); assertLocalEndpoint() rejects any non-local host unless LLM_ALLOW_REMOTE=1.
